# Implementation plan (phase-1-app)

Active phase: `phase-1-app` (PostgreSQL store and runnable project API). Module path: `taskboard`. Verification for every bead: `cd taskboard && go test ./...`.

## Bead map

### ta-11e: taskboard/internal/store/postgres.go
- Scope: PostgreSQL implementation of the shared `Store` interface, opened through `NewPostgresStore`.
- Architecture: `taskboard/internal/store/postgres.go` implements PostgreSQL storage with transactional advisory locks for schema setup (architecture.md, Components and Module ownership).
- Interfaces: `NewPostgresStore(databaseURL string) (Store, error)`; the returned value satisfies every method of `Store` declared in `store.go`, with the same contract as the SQLite store.
- Depends on: `taskboard/internal/store/store.go` (phase-1-core: `Store`, `ErrNotFound`, DDL constants), `taskboard/internal/model/model.go`.
- Consumed by: `taskboard/cmd/taskboard/main.go` (driver selection), `taskboard/internal/store/postgres_integration_test.go`.
- Acceptance:
  - Schema setup runs inside a single transaction that first takes a PostgreSQL advisory lock (`pg_advisory_xact_lock`), then creates the projects and tasks tables only if absent, so simultaneous starts do not race and repeated starts are no-ops.
  - Schema setup never drops or truncates existing tables.
  - All SQL uses `$1`-style placeholders (pgx stdlib), never `?`.
  - `tasks.project_id` is a foreign key to `projects(id)` with `ON DELETE CASCADE`, so deleting a project removes its tasks.
  - Identity primary keys are generated by PostgreSQL, and timestamps are stored and returned in UTC.
  - Missing rows on get, update, and delete return `ErrNotFound`. List methods return non-nil empty slices when there are no rows.
  - No SQLite PRAGMA statements appear in this file.
- Verify: `cd taskboard && go test ./...` (integration cases skip unless `TASKBOARD_TEST_POSTGRES_URL` is set).

### ta-82r: taskboard/internal/store/store_test.go
- Scope: shared contract tests run against the SQLite-backed `Store` through the interface.
- Architecture: store contract tests in `taskboard/internal/store/store_test.go`.
- Interfaces: test-only package `store_test`; exports nothing.
- Depends on: `NewSQLiteStore` (phase-1-core, `taskboard/internal/store/sqlite.go`), `Store`, `ErrNotFound`, `TaskPatch`, `TaskFilter` (store.go).
- Consumed by: none.
- Acceptance:
  - Get, update, and delete on a missing ID return an error where `errors.Is(err, store.ErrNotFound)` holds, for projects and tasks.
  - `ListProjects` on an empty store returns a non-nil empty slice; `ListTasks` on a project with no tasks does too.
  - Tests use `t.TempDir()` and never touch a shared database file.
- Verify: `cd taskboard && go test ./internal/store/...`.

### ta-5qb: taskboard/internal/store/postgres_integration_test.go
- Scope: PostgreSQL integration tests of the `Store` interface, gated on `TASKBOARD_TEST_POSTGRES_URL`.
- Architecture: exercises the store against a live PostgreSQL database for advisory-lock schema setup, identity primary keys, UTC timestamp precision, `$1` placeholder behavior, and foreign key cascade deletion.
- Interfaces: test-only; exports nothing.
- Depends on: `NewPostgresStore` (`taskboard/internal/store/postgres.go`), `Store`, `ErrNotFound`.
- Consumed by: none.
- Acceptance:
  - Two concurrent `NewPostgresStore` calls against an empty schema both succeed and leave one projects table and one tasks table.
  - Deleting a project removes its tasks (`ON DELETE CASCADE`).
  - Created timestamps round-trip in UTC.
  - Test is skipped with `t.Skip` when `TASKBOARD_TEST_POSTGRES_URL` is empty, so `go test ./...` passes without a database.
- Verify: `cd taskboard && go test ./internal/store/...`.

### ta-5kn: taskboard/cmd/taskboard/main.go
- Scope: process entrypoint that loads configuration, selects the driver, initializes the store, builds the app, and serves HTTP with graceful shutdown.
- Architecture: entrypoint for startup, configuration loading, database initialization, and graceful SIGTERM shutdown.
- Interfaces: `func main()`; uses `config.LoadConfig() (Config, error)`, `store.NewSQLiteStore`, `store.NewPostgresStore`, `web.NewApp(s store.Store) *web.App`, and `(*web.App).Handler()`.
- Depends on: `taskboard/internal/config/config.go`, `taskboard/internal/store/store.go`, `taskboard/internal/store/sqlite.go`, `taskboard/internal/store/postgres.go`, `taskboard/internal/web/app.go`.
- Consumed by: none (process entrypoint).
- Acceptance:
  - Config is loaded from `TASKBOARD_*` environment variables before any store is opened.
  - `TASKBOARD_DB_DRIVER=postgres` selects `NewPostgresStore` with `TASKBOARD_DATABASE_URL`; any other driver value selects SQLite.
  - The store is opened before the HTTP server starts; a failure exits non-zero with a message.
  - Listens on `TASKBOARD_HOST` and `TASKBOARD_PORT` (default port 8080).
  - SIGINT and SIGTERM trigger `http.Server.Shutdown` with a bounded timeout, then the store is closed.
- Verify: `cd taskboard && go build ./cmd/taskboard && go test ./...`.

### ta-12r: taskboard/internal/web/app.go
- Scope: HTTP router construction and page/static routes.
- Architecture: `app.go` builds the HTTP router; `App` struct and `NewApp` function are owned here.
- Interfaces: `type App struct` (holds `store.Store` and the mux); `func NewApp(s store.Store) *App`; `func (a *App) Handler() http.Handler`.
- Depends on: `taskboard/internal/store/store.go` (`Store`), `taskboard/web/assets.go` (`FS`).
- Consumed by: `taskboard/cmd/taskboard/main.go`, `taskboard/internal/web/api.go` (`registerAPI` is called from `NewApp`).
- Acceptance:
  - `NewApp` builds a mux, registers `GET /` (serves `templates/index.html` from `FS` with `Content-Type: text/html; charset=utf-8`), calls `registerAPI`, and returns the `App`.
  - the static asset route serves files from `static/` in `FS` with correct content types (phase 2 adds the files; the route must already be registered).
  - Unknown paths are not served by the index handler (`GET /{$}` only matches the root).
  - No SQL statements appear in this file.
- Verify: `cd taskboard && go test ./internal/web/...`.

### ta-83w: taskboard/internal/web/api.go
- Scope: REST API route handler methods on `App`.
- Architecture: `api.go` builds the REST API endpoints.
- Interfaces: method set on `*App` registered by `registerAPI()`, covering the routes in the table below; JSON helper `writeJSON(w, status, v)` from app.go.
- Depends on: `App` and `writeJSON` (`app.go`), `store.Store`, `ErrNotFound`, `model` validation functions.
- Consumed by: `app.go` (`NewApp` calls `registerAPI`).
- Routes registered (must match SPEC exactly):
  - `GET /api/health` returns `{"status":"ok"}`.
  - `GET /api/ready` pings the store and returns a non-2xx status on failure.
  - `GET /api/projects`, `POST /api/projects` (body `{"name":"..."}`).
  - `DELETE /api/projects/{project_id}`.
  - `GET /api/projects/{project_id}/tasks` (optional `status`, `priority` query filters), `POST /api/projects/{project_id}/tasks`.
  - `PATCH /api/tasks/{task_id}`, `DELETE /api/tasks/{task_id}`.
- Acceptance:
  - `ErrNotFound` maps to HTTP 404; validation failures map to 400; unexpected store errors map to 500.
  - Create returns 201 with the created entity; delete returns 204 or 200 consistently.
  - Invalid path IDs return 400.
  - `GET /api/ready` reflects a live store ping, not a constant.
- Verify: `cd taskboard && go test ./internal/web/...`.

  - No business logic and no `..` in embed patterns.
- Verify: `cd taskboard && go test ./internal/web/...`.

### ta-8l7: taskboard/internal/web/api_test.go

## Integration contract

Active phase includes `taskboard/cmd/taskboard/main.go`, so this section is required.

### Startup / dependency order
1. phase-1-core (completed): `store/store.go`, `store/sqlite.go`, `model/model.go`, `config/config.go` must exist and compile before phase-1-app beads start.
2. `taskboard/internal/store/postgres.go` (ta-11e) depends on `store.go` for `Store`, `ErrNotFound`, and DDL constants.
3. `taskboard/web/assets.go` (ta-qfs) depends on `taskboard/web/templates/index.html` (ta-dw6).
4. `taskboard/internal/web/app.go` (ta-12r) depends on `store.go` (`Store`) and `assets.go` (`FS`).
5. `taskboard/internal/web/api.go` (ta-83w) depends on `app.go` (`App`, `writeJSON`).
6. `taskboard/cmd/taskboard/main.go` (ta-5kn) depends on `config.go`, `store.go`, `sqlite.go`, `postgres.go`, `app.go`; it is planned last because it wires all of them.
7. Test beads (ta-82r, ta-5qb, ta-8l7) depend on the code beads they exercise.

Wire order in main: `config.LoadConfig` -> open store (`NewSQLiteStore` or `NewPostgresStore`) -> `web.NewApp(s)` -> `http.Server{Handler: app.Handler()}` -> serve -> on SIGINT/SIGTERM call `Shutdown` then close the store.

### Per-file exports
- `taskboard/internal/store/postgres.go`: `NewPostgresStore` (returns a `Store`).
- `taskboard/internal/store/store.go` (consumed): `Store`, `ErrNotFound`, `TaskPatch`, `TaskFilter`.
- `taskboard/web/assets.go`: `FS`.
- `taskboard/internal/web/app.go`: `App`, `NewApp`, `(*App).Handler`.
- `taskboard/internal/web/api.go`: API route methods on `*App` registered by `registerAPI` (no new exported package-level symbols).
- `taskboard/cmd/taskboard/main.go`: `main`.
- Test files export nothing.

### Routes (must agree with SPEC and api.go)
`GET /`, `GET /api/health`, `GET /api/ready`, `GET /api/projects`, `POST /api/projects`, `DELETE /api/projects/{project_id}`, `GET /api/projects/{project_id}/tasks`, `POST /api/projects/{project_id}/tasks`, `PATCH /api/tasks/{task_id}`, `DELETE /api/tasks/{task_id}`.

### Module path
All imports use `taskboard/...` (for example `taskboard/internal/store`, `taskboard/web`).
