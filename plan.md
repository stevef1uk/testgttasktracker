# Implementation plan — phase-1-core

Scope: Go foundation, configuration, models, shared store contract, and SQLite store. Only the eight paths in `required_files` for `phase-1-core` are owned by this phase. Later phases (`phase-1-app` and beyond) get their own beads.

Verify gate (active phase): `cd taskboard && go mod verify && go test ./internal/config ./internal/model ./internal/store`

## Bead map

### ta-92w: taskboard/go.mod
- Scope: Declare module `taskboard`, `go 1.25+`, and require `modernc.org/sqlite` (pure Go, CGO disabled). Do not require pgx in this phase.
- Architecture: Go foundation; SPEC §2 fixed constraints; SPEC §3 canonical layout.
- Acceptance: `go mod verify` succeeds; `taskboard/go.mod` contains only dependencies needed by phase-1-core packages.

### ta-451: taskboard/go.sum
- Scope: Lockfile generated by dependency resolution (`go mod tidy`), never handwritten.
- Architecture: SPEC §2 requires committed `go.mod`/`go.sum`.
- Acceptance: `go mod verify` passes; `taskboard/go.sum` matches `taskboard/go.mod` after tidy.

### ta-f1f: taskboard/README.md
- Scope: Document configuration variables, the phase-1-core package layout, and the gate command.
- Architecture: SPEC §4 configuration table; SPEC §10 gate.
- Acceptance: README lists TASKBOARD_DB_DRIVER, TASKBOARD_DB_PATH, TASKBOARD_DATABASE_URL, TASKBOARD_HOST, and TASKBOARD_PORT with their defaults; no live credentials.

### ta-b55: taskboard/.gitignore
- Scope: Exclude built binaries, `*.db` SQLite files, `node_modules`, and reports.
- Architecture: SPEC §2 forbids committing databases, binaries, and `node_modules`.
- Acceptance: `git check-ignore` matches `taskboard/taskboard.db`, `taskboard/bin/`, and `taskboard/node_modules/`.

### ta-93p: taskboard/internal/config/config.go
- Scope: `Config` struct and `LoadConfig()` reading TASKBOARD_DB_DRIVER (`sqlite` default, or `postgres`), TASKBOARD_DB_PATH (default `taskboard.db`), TASKBOARD_DATABASE_URL, TASKBOARD_HOST (default `127.0.0.1`), and TASKBOARD_PORT (default 8080, integer 1–65535).
- Architecture: SPEC §4; invalid config fails startup with a useful error.
- Acceptance: unknown driver is rejected; postgres with empty URL is rejected; port 0, 65536, and non-integer values are rejected; defaults apply when variables are unset; the error text never echoes a URL or password. Tests run through `go test ./internal/config` in `taskboard/`.

### ta-i6d: taskboard/internal/model/model.go
- Scope: `Project` and `Task` structs; Unicode code-point validators using `utf8.RuneCountInString`; project name trimmed and 1–80 code points; task title trimmed and 1–120 code points; description at most 1000 code points and retained verbatim; `ValidateDescription`; status enum exactly `todo`/`doing`/`done` with default `todo`; priority enum exactly `low`/`medium`/`high` with default `medium`.
- Architecture: SPEC §5 data model and invariants; architecture.md assigns validation to `taskboard/internal/model/model.go`, not SQL or HTTP.
- Acceptance (this bead was previously closed without these; reopen and complete):
  - Name and title limits: 80 and 120 code points; boundary values 1 and max accepted, 0 and max+1 rejected; multi-byte runes count as one code point.
  - Description limit: 1000 code points; 1001 rejected; description is not trimmed.
  - Status and priority enum validators accept only the listed values; empty, uppercase, and unknown values are rejected.
  - Trimming applies to names and titles only.
  - Tests for these cases run through `go test ./internal/model` in `taskboard/`.

### ta-xea: taskboard/internal/store/store.go
- Scope: `Store` interface with context-first methods; repository error values (`ErrNotFound` and similar); shared DDL constants for `projects` and `tasks` (including the `project_id` index and the `ON DELETE CASCADE` foreign key).
- Architecture: architecture.md assigns Store and DDL to `taskboard/internal/store/store.go`, not HTTP routing.
- Acceptance: the interface declares the CRUD and filter methods the SQLite store implements; the package compiles with `go build ./internal/store/...` in `taskboard/`.

### ta-zmd: taskboard/internal/store/sqlite.go
- Scope: `NewSQLiteStore(path)` opening `modernc.org/sqlite`; foreign keys enabled on every pooled connection through DSN configuration (a single PRAGMA is insufficient); 5000 ms busy timeout; schema creation on open that is idempotent on repeat; CRUD for projects and tasks with `?` placeholders; filters by status and priority that combine with AND; ordering by ascending `id`; UTC RFC3339 timestamps; close and reopen persistence.
- Architecture: SPEC §5; architecture.md assigns SQLite only to `taskboard/internal/store/sqlite.go`, with no Postgres dialect syntax.
- Acceptance (this bead's verify is still open; the prior attempt closed the write but the test file was not written):
  - Fresh schema is empty; repeated initialization is idempotent.
  - Project create/list in ascending ID order.
  - Task create defaults to status `todo` and priority `medium`; `created_at` and `updated_at` are UTC.
  - Filters by status, by priority, and by both together.
  - Patch of all mutable fields preserves omitted fields.
  - Deleting a project cascades to its tasks; foreign key enforcement is verified.
  - Data persists across close and reopen.
  - Tests use `t.TempDir()` and never touch `taskboard.db`.
  - Tests run through `go test ./internal/store` in `taskboard/`.

## Ordering and dependencies
1. ta-92w (`taskboard/go.mod`) and ta-451 (`taskboard/go.sum`) first.
2. ta-93p (config), ta-i6d (model), and ta-xea (store interface) next; ta-xea depends on ta-i6d for types.
3. ta-zmd (`taskboard/internal/store/sqlite.go`) last; it depends on ta-xea and ta-i6d.
4. ta-f1f (`taskboard/README.md`) and ta-b55 (`taskboard/.gitignore`) may land at any point after go.mod.
