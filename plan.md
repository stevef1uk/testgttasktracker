# Implementation plan — phase-1-core

Active phase: `phase-1-core` (Go foundation, configuration, models, SQLite store). Only the eight paths in `required_files` are in scope. Later-phase files (`taskboard/internal/store/postgres.go`, `taskboard/cmd/taskboard/main.go`, `taskboard/internal/web/app.go`, `taskboard/internal/web/api.go`, `taskboard/web/assets.go`, deploy files) are deferred and must not get beads or acceptance criteria here.

Phase verification: `cd taskboard && go mod verify && go test ./internal/config ./internal/model ./internal/store`

## Bead map

### ta-lc8: taskboard/go.mod
- Scope: Go module manifest for the taskboard application (Go 1.25+).
- Architecture: Planned file layout; phase-1-core required_files.
- Interfaces: module declaration only; requires `modernc.org/sqlite`. The PostgreSQL driver `github.com/jackc/pgx/v5/stdlib` is not added in this phase.
- Depends on: `<none>`
- Consumed by: ta-lhb (`taskboard/go.sum`), ta-gd2 (`taskboard/internal/config/config.go`), ta-4rb (`taskboard/internal/model/model.go`), ta-f34 (`taskboard/internal/store/store.go`), ta-dwi (`taskboard/internal/store/sqlite.go`)
- Acceptance:
  - File exists at `taskboard/go.mod` with a Go 1.25+ `go` directive.
  - Declares `modernc.org/sqlite` as a direct requirement.
  - `cd taskboard && go mod verify` succeeds once go.sum exists.
- Verify: `cd taskboard && go mod verify`
- Bead `ta-lc8` is closed only after verification passes.

- Architecture: Module ownership table (exports `Config` struct and `LoadConfig` function); Requirements phase-1-core.
- Interfaces: `type Config struct` with driver, SQLite path, database URL, host, and port fields; `func LoadConfig() (Config, error)`.
- Depends on: ta-lc8 (`taskboard/go.mod`)

- Acceptance:

  - Contains no database queries and no HTTP handler code.
  - Unit tests in `taskboard/internal/config` cover defaults and explicit env values.
- Verify: `cd taskboard && go mod tidy && go test -timeout 30s -count=1 ./internal/config/...`
- Bead `ta-gd2` is closed only after verification passes.

### ta-4rb: taskboard/internal/model/model.go
- Scope: Domain types and validation.
- Architecture: Module ownership table (exports `Project`, `Task`, `Status`, `Priority`, `TaskFilter`, `ValidateProject`, `ValidateTask`); Overview (code-point validation via `utf8.RuneCountInString`).
- Interfaces: `type Project struct`, `type Task struct`, `type Status` (todo, doing, done), `type Priority` (low, medium, high), `type TaskFilter struct`, `func ValidateProject`, `func ValidateTask`.
- Depends on: ta-lc8 (`taskboard/go.mod`)
- Consumed by: ta-f34 (`taskboard/internal/store/store.go`), ta-dwi (`taskboard/internal/store/sqlite.go`)
- Acceptance:
  - Status values are exactly todo, doing, done; Priority values are exactly low, medium, high.
  - Length checks use `utf8.RuneCountInString`, not byte length.
  - Contains no SQL DDL and no HTTP response code.
  - Unit tests in `taskboard/internal/model` cover valid and invalid enum values and rune-length boundaries.
- Verify: `cd taskboard && go mod tidy && go test -timeout 30s -count=1 ./internal/model/...`
- Bead `ta-4rb` is closed only after verification passes.

### ta-f34: taskboard/internal/store/store.go
- Scope: Shared Store interface, repository errors, and SQL DDL constants.
- Architecture: Module ownership table (exports `Store` interface, `ErrNotFound`, DDL schema constants); Requirements phase-1-core.
- Interfaces: `type Store interface` with context-aware project and task operations; `var ErrNotFound`; DDL constants used by `taskboard/internal/store/sqlite.go`.
- Depends on: ta-4rb (`taskboard/internal/model/model.go`), ta-lhb (`taskboard/go.sum`)
- Consumed by: ta-dwi (`SQLiteStore` implements `Store`)
- Acceptance:
  - Store methods take `context.Context` and use model types from `taskboard/internal/model`.
  - `ErrNotFound` is returned for missing rows.
  - Contains no HTTP routing and no driver-specific PRAGMA or PostgreSQL SQL.
  - `cd taskboard && go build ./internal/store/...` succeeds.
- Verify: `cd taskboard && go mod tidy && go build ./internal/store/...`
- Bead `ta-f34` is closed only after verification passes.

### ta-dwi: taskboard/internal/store/sqlite.go
- Scope: SQLite implementation of `Store` using modernc.org/sqlite.
- Architecture: Module ownership table (exports `SQLiteStore` and `NewSQLiteStore`); Components (foreign_keys on every connection via `_pragma=foreign_keys(1)`, 5000ms busy timeout).
- Interfaces: `type SQLiteStore struct`; `func NewSQLiteStore(path string) (*SQLiteStore, error)`; satisfies `Store` from `taskboard/internal/store/store.go`.
- Depends on: ta-f34 (`taskboard/internal/store/store.go`), ta-4rb (`taskboard/internal/model/model.go`), ta-gd2 (`taskboard/internal/config/config.go`)
- Consumed by: store tests in `taskboard/internal/store/store_test.go` (later phase)
- Acceptance:
  - Every connection enables foreign keys through `_pragma=foreign_keys(1)`.
  - Busy timeout is 5000 ms.
  - Schema comes from the DDL in `taskboard/internal/store/store.go`; re-running schema init is idempotent.
  - Deleting a project cascades to its tasks; inserting a task for an unknown project fails.
  - Missing task or project returns `ErrNotFound`.
  - All user input is parameterized.
  - Tests use `t.TempDir()` database files, never the runtime `taskboard.db`.
- Verify: `cd taskboard && go mod tidy && go test -timeout 30s -count=1 ./internal/store/...`
- Bead `ta-dwi` is closed only after verification passes.
